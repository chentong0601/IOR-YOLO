## 总体推进流程

原则：文献、数据和代码联合调研；将小规模可行性验证提前；根据证据凝练 idea，再冻结正式研究路线。允许迭代，不以预设方法或正向结果约束结论。

| 阶段 | 工作 | 阶段产出与进入下一阶段的依据 |
|---|---|---|
| 1. 建立研究档案 | 整理项目说明、目标、资源和待确认问题 | 区分已确认事实、候选假设和建议 |
| 2. 联合调研 | 阅读最接近文献，核查数据，比较成熟 GitHub 项目与方法 | 找到可信数据基础、创新空间和可复现基线 |
| 3. 候选 idea 成熟化 | 提出少量假设，说明机制、区别、验证及否定条件 | 每个假设都有能够支持或推翻它的实验 |
| 4. 最小可行性验证 | 数据审计、基线复现、错误分析和小规模方法试验 | 确认问题存在、指标有区分度、方法有初步依据 |
| 5. 冻结正式路线 | 确定任务、方法、划分、指标、对照和预算 | 形成可执行、可审查的实验协议 |
| 6. 完整实验与分析 | 多种子、消融、公平对比、鲁棒性和外部评价 | 所有结论可追溯，负面结果和局限得到分析 |
| 7. 论文整合与投稿 | 完成论证、图表、复现材料与投稿准备 | 论文主张与证据一致 |

以上流程是本轮讨论形成并要求保存的工作计划。进入具体执行阶段时，以用户后续指示为准；不将“仍在讨论”解释为永久限制。

对最接近的工作记录：

5. 与候选 idea 的重叠、区别和待验证优势。
6. 依赖、修改成本、计算要求和复用条件。

## 候选研究方向：尚未冻结

当前建议主线：光照变化下的苹果阶段判断准确性与稳定性，重点观察严重跨级误判，同时要求常规检测性能基本保持。

候选假设：在尽量保留阶段相关色彩信息的光照变化下，序数监督与目标级一致性学习能够减少严重跨级误判，同时维持检测性能。

此方向是待验证建议，不能记作已证明结论或最终选题。跨数据集泛化作为补充证据；题目中的“域鲁棒”主张是否成立，需根据数据和正式实验决定。

优先核查事项：

- 四个类别描述的是成熟度还是生长阶段？原始标签由什么依据确定？
- 是否存在场景、时间序列或近重复泄漏？
- 光照变化主要导致漏检、相邻阶段混淆，还是严重跨级误判？
- 基线严重误判是否足够多，SER 是否适合作为主要指标？
- 辅助序数头改善能否传递到最终检测类别？
- Lab 亮度扰动转回 RGB 后是否产生色偏或裁剪？
- Fuji 与主数据的成熟标签是否语义兼容？不能仅按类别名映射。
- 与现有序数学习、光照增强和一致性方法的实质区别是什么？

## 实验原则

- 区分探索实验与正式实验：方法开发和参数选择使用训练集、验证集；最终测试集及其扰动版本在方案冻结后用于最终评价。
- 不沿用原说明书中先看最终 test 的 E03 结果、再据此开发方法的顺序。问题诊断应先在验证集完成。
- 先审计数据，再做单种子基线与小规模诊断；确认路线有依据后，再投入多种子和完整矩阵。
- 分别验证序数监督、光照增强，随后判断一致性机制是否提供额外收益。
- 同时检查准确性与一致性，避免把“一直预测错”视为改善。
- 正式方案考虑普通增强对照、相同双视图训练预算的无一致性对照，以及未见扰动测试。
- 合成扰动、自然光照分组、跨数据集测试各有不同解释范围；外部收益不能直接归因于光照因素。
- 保留失败结果与停止条件，不以模块数量、单次提升或预设成功百分比代替证据。
